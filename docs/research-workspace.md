# RefMind 科研工作台运行与验收

新工作台使用 Vue 3、TypeScript 和 FastAPI，保留问答与原文并排研读。当前交付覆盖本地科研检索、显式外部论文发现、私有全文任务、可选入库和可追踪测评。完整 600 题人工金标准及独立质量验收仍在建设中，不能用离线测试或界面演示替代。

## 启动工作台

以下命令在项目根目录执行。启动前先停止旧 Streamlit 写入进程。首次账号需要管理员在本机创建，密码通过交互输入；源码没有默认账号。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
npm --prefix frontend ci
npm --prefix frontend run build
.\.venv\Scripts\python.exe -m refmind.web.manage create-user admin --admin
.\scripts\start_research.ps1
```

浏览器打开 `http://127.0.0.1:8000`。管理页可以继续创建普通账号；资料访问以库成员权限和会话所有者为准，管理员身份不自动取得其他用户私有资料。

内网监听使用 `scripts/start_research.ps1 -BindAddress 0.0.0.0 -Port 8000`。共享使用应由可信反向代理终止 HTTPS，并在服务环境设置 `REFMIND_COOKIE_SECURE=true`。默认脚本仅监听本机，当前交付没有修改 Windows 防火墙、安装自启动服务或部署到内网服务器。

API 与前端同源；Vite 开发代理仅用于开发。服务采用单个 Uvicorn 进程，后台任务池允许不同会话并行，不要用多个 Uvicorn worker 写同一数据库。健康入口为 `/api/health`，接口定义为 `/docs`。

## 旧资料迁移与回退

旧库没有账户归属，不会自动变成共享库。停止写入服务后，列出并显式登记旧库：

```powershell
.\.venv\Scripts\python.exe -m refmind.web.manage unclaimed-libraries
.\.venv\Scripts\python.exe -m refmind.web.manage claim-library 旧库ID 账号
```

登记只赋予该账号私有所有权，不重写论文和向量。数据库增加独立账户、成员、任务和证据表，旧数据结构继续保留。未关联新账户的历史会话仍属于旧界面记录，不会自动展示给新账号。

API、离线管理与 Streamlit 使用同一数据库写入锁，不能同时运行。已经建立团队账号的数据库默认禁止旧 Streamlit 启动，以免旧界面绕过私有库权限；管理员需要本机回退时，先停 API，再设置 `REFMIND_LEGACY_ADMIN_MODE=true` 并以 `--server.address 127.0.0.1` 启动 Streamlit。该模式面向本机管理员，不提供团队账户隔离。

## 论文发现与全文状态

默认研读模式只使用选定的本地库。外部检索由用户提交搜索触发，`auto` 查询 Semantic Scholar、OpenAlex 和 Crossref，OpenAlex 无 Key 时也会尝试基础查询。来源限流或失败会分别报告；已经返回的候选可以先显示，不用摘要问答成功代替发现成功。

候选保留无摘要题录、多来源字段、来源冲突和公开位置的版本。DOI 用于作品关联；相同题名不自动合并。日期排序在当前取回结果中执行，页面标注范围。恢复任务会恢复原检索词、来源、筛选与分页条件。

勾选候选只改变研读选择，点击获取全文才下载。下载检查每次跳转的公网地址、端口、大小、超时和真实 PDF 格式，记录 SHA256 与题名或 DOI 身份核验结果。只有原站网页时提供跳转及上传方式，不把网页当作 PDF。

状态依次为候选链接、下载、核验、解析、索引、就绪。身份冲突不能继续；无法自动核验时，用户查看原文后明确确认。部分页解析失败会显示可用范围，必须确认仅研读已解析部分。选择全文后问答不会静默换成另一篇论文。

全文默认属于发起者的私有会话，保留 7 天。保存到文献库需具有编辑权限；同一文件指纹重复保存返回既有文档，不同文件版本单独保留。会话副本过期不删除正式库副本，历史回答保留最小证据快照并明确原文不可用。

失败或取消的本地上传暂存为重试保留最多 7 天；过期需要重新上传。任务状态保存在数据库，重启将未完成任务标为中断，用户可以显式重试。模型请求已经发出时，取消在当前请求返回后生效；已产生的费用仍记账。

## 科研证据与测评接口

本地上传和公开全文共用解析、切分、向量索引及原文定位。MinerU 坐标转换为 PDF 坐标；原始表格和公式保持完整，超出预算时按明确表格行生成受限视图或舍弃，并记录缺失。

检索先过滤就绪文档与选定范围。比较问题按论文分配证据，总结问题补充章节，其他问题可追加同节相邻块。科学单位别名保留大小写和原文，不擅自换算。新入库数据携带文件哈希、解析依赖、切分参数及嵌入配置指纹。

`PaperCandidate` 位于 `services/paper_discovery.py`，`ResearchScope`、`AnswerResult` 和 `EvaluationTrace` 位于 `contracts.py`，`EvidenceBundle` 位于 `rag/evidence_bundle.py`。实际产品流程由 `rag/research_pipeline.py` 与 `graph.answer_from_evidence` 组成，旧评测主线可继续选择 `legacy`。

Trace 分开保存召回、重排、装配后的证据、实际生成上下文和最终引用。审核后再次检查访问权限和资料状态；最终引用位置还需人工评估其科研支撑关系，模型审校不等于人工认证。

生成、证据审核和答案审核分别计时与记账。运行参数可通过评测 CLI 的 `--set` 注入隔离子进程；报告核对实际生效值，不写回 `.env`。可切换两个审核开关及拒答复核开关，支持方案中的消融对照。

## 模型与费用

`CHAT_PROVIDER`、`EMBEDDING_PROVIDER`、`VISION_PROVIDER` 可分别设为 `openai` 或 `dashscope`。本次没有修改 `.env`，工作台沿用本机配置。OpenAI 嵌入在新 API 使用独立索引目录，不复用 DashScope 向量；更换嵌入供应商需为目标配置重新建立索引，不会自动付费迁移历史库。

OpenAI 沿用阶段 1 的固定模型和 `data/openai_usage.sqlite3` 账本，默认每日 2 美元、累计 10 美元。失败且用量未知的请求继续占用预留额度，不能删除账本重试；账本金额是应用估算，不替代供应商账单。DashScope 结果须与 OpenAI 单独保存，当前跨供应商统一费用核算尚未作为验收通过项。

## 备份与恢复

先停止 API、Streamlit 和评测写入进程，再执行备份：

```powershell
.\.venv\Scripts\python.exe -m refmind.web.manage backup D:\RefMindBackups\research-20261105.zip
.\.venv\Scripts\python.exe -m refmind.web.manage restore D:\RefMindBackups\research-20261105.zip D:\RefMindRestore\verify-20261105
```

归档包含数据库、原文、解析资产、向量目录、会话资料与独立费用账本，记录逐文件大小与 SHA256，并产生整包校验文件；密钥配置需要另外安全保管。普通 `restore` 只验证提取，查看生成的 `RESTORE-INSTRUCTIONS.txt`。

SQLite、Chroma 和解析元数据可能保存绝对路径，因此正式安装使用 `restore ... --original-paths`，要求当前配置与归档一致、全部原数据目标不存在。命令拒绝覆盖已有资料或费用账本，不能把旧备份强行覆盖新数据。恢复后先验证登录、文献、原文引用和检索，再开放服务。已经使用真实 Chroma 写入与查询完成离线恢复测试；没有替换日常运行数据。

## 历史索引的显式重建（第023轮）

已经核对原文、独立入库记录和历史嵌入配置的旧文献，可在停止API、Streamlit及测评写入进程并备份后逐篇重建。命令保留文献ID、原文路径、库内编号与历史引用，生成新的索引版本。先核对原解析记录或来源登记中的SHA256，不从可疑索引片段提取指纹，也不以现有文件的临时计算值替代历史来源核对。

```powershell
.\.venv\Scripts\python.exe -m refmind.web.manage reindex-legacy 文献ID --expected-sha256 已核对的64位小写文件SHA256
```

原文指纹、来源记录冲突，或历史嵌入供应商/模型缺失或不同，命令会停止。它不执行跨供应商迁移。解析和嵌入沿用当前配置，实际运行可能产生费用，继续受原账本与限额约束。

重建失败或被中断时，原文、旧解析、图片和历史证据保留，文献暂停新问答，启动清理不删除这些记录。确认原文和配置后用同一命令重试。已成功且指纹匹配的文献重复调用不会再嵌入。初期仅提供离线管理入口，不会自动迁移所有旧文献。不要在存在reindexing/reindex_failed状态时回退到旧版启动清理代码。

隔离验证与限制见 [第023轮验收报告](../evaluation/reports/staged-acceptance/20261106-023/REPORT.md)。


## 工作台维护申请与离线执行（第024轮）

文献详情新增“索引与证据状态”。所有者或编辑可在原文和独立历史记录核对通过后申请维护；只读成员只查看状态。申请保存在任务中心，支持撤回、失败后重新申请和刷新恢复。等待维护计入每人10项待处理任务限额。它不会由在线任务执行器自动解析或调用模型。

操作人取得申请编号后，先停止API、Streamlit及其他写入进程、完成备份，并从原解析记录或来源登记独立核对SHA256，再逐项执行：

```powershell
.\.venv\Scripts\python.exe -m refmind.web.manage run-reindex-request 申请编号 --expected-sha256 已独立核对的64位小写文件SHA256
```

命令重新检查申请人的账号和库编辑权限、原文指纹与历史嵌入配置，取得独占写入锁后执行第023轮重建。真实解析/嵌入可能产生费用，继续沿用原账本及限额。失败时状态保留，确认原因后由申请人在工作台显式重新申请；重新启动服务后可查看最终状态。已提交新索引但任务结果写回失败时，重试只补齐完成状态。

申请不等于已经重建；没有历史来源记录、半缺失身份或配置冲突的文献仍需人工核对。初期管理员按申请编号安排停服维护，没有在线执行或自动批量迁移。回退本版本前先处理待维护申请，不把此类任务交给旧版通用重试入口；继续保留第021/023轮的版本校验和重建中间态保护。

隔离工程与浏览器验证见 [第024轮报告](../evaluation/reports/staged-acceptance/20261106-024/REPORT.md)。日常文献库未迁移，科研质量仍需单独验收。
